# AGENTS.md: context for AI coding agents

This file is for AI coding agents (Claude Code, Codex, Copilot, Cursor, ...). It holds the
context a new agent needs before changing this repo. Humans: start at [docs/README.md](docs/README.md)
instead. `CLAUDE.md` imports this file.

**Keep it current.** If you change something this file describes (a rule, a command, a file's
job, an endpoint, a config key), update this file in the same pull request. If you make a
design decision a future maintainer would ask "why?" about, add it to
[docs/decisions.md](docs/decisions.md).

## What this is

Ground station for UTD Comet Rocketry (IREC 2027 **Team 1100**, **10K Liquid** category). The
vehicle is **Hestia**, powered by our liquid engine **RANGER-1** (nitrous oxide + isopropyl
alcohol). These live in the `[mission]` / `[rocket]` config sections (`GET /api/mission`), not
hardcoded in the UI. A Raspberry Pi receives the
rocket's telemetry over a serial radio, logs it to disk, and shows it in a browser dashboard.
Python FastAPI backend + React/TypeScript frontend. It must work **fully offline** at the
launch site.

## Hard rules (do not break these)

1. **Monitoring only. No uplink.** Nothing may transmit to the rocket. No endpoint, button or
   serial write that commands the flight computer. The only serial writes allowed are local,
   read-only XBee AT queries (`DB` for RSSI) answered by the ground module itself;
   `sources/xbee.py` refuses to build anything else.
2. **Never hardcode a radio frequency.** Frequencies are set on the radio hardware per the
   team's IREC assignment.
3. **The mode is always visible and never mixed.** SIMULATION / LIVE / REPLAY is shown in the
   banner. Switching modes clears in-memory history and starts a new recording session.
   Simulated data must never be presentable as real.
4. **Record before display.** `TelemetryHub.handle_packet` writes the frame to the recorder
   *before* broadcasting it. Keep that order.
5. **Recording failures are non-fatal.** A disk error sets `recording_error` (UI shows
   "RECORDING FAILED") and telemetry keeps flowing. Never let a recorder exception stop the
   telemetry loop. Same for a crashing source: it sets `source_error`, the server stays up.
6. **`None` is not `0`.** Missing fields stay `null` (JSON) / empty (CSV) and show "NO DATA".
   Never substitute zero.
7. **Phase comes from the rocket.** The flight computer's FSM state byte decides the phase.
   The hub only names transitions (PAD→BOOST = "Liftoff"). Do not infer apogee or deployment
   on the ground.
8. **Ground log ≠ flight log.** `data/sessions/*` is what the ground received. The onboard SD
   log and the COTS altimeter are the official records.
9. **No secrets in git.** Never commit passwords (including the Pi login), keys, real launch
   coordinates, or `config/ground_station.toml`. The simulator's GPS origin is synthetic on
   purpose.
10. **No internet at runtime.** No CDN scripts, web fonts, map tiles or API calls from the
    dashboard. Everything is bundled by Vite and served by the backend.
11. **Decorative things stay off the flight screens.** The ASCII art (About page, sidebar
    rocket, terminal splash) must never cover or slow down flight data. Pause animations when
    hidden; respect `prefers-reduced-motion`.

## Layout

```
backend/ground_station/
  __main__.py        CLI entry: python -m ground_station [--mode LIVE --serial-port ...]
  config.py          loads config/ground_station.toml (example: config/ground_station.example.toml)
  schema.py          FlightData / TelemetryFrame / FlightEvent (pydantic), CSV_COLUMNS, Mode, phases
  hub.py             TelemetryHub: one active source -> link stats -> record -> broadcast; phase events
  recorder.py        SessionRecorder: append-only CSV, fsync every 1 s
  server.py          FastAPI app: REST /api/*, WebSocket /ws, serves frontend/dist
  rocket_model.py    parses the OpenRocket .ork (outline, fins, predicted flight)
  sources/
    base.py          TelemetrySource ABC, SourcePacket, RejectedPacket
    simulation.py    synthetic flight (labelled SIMULATION)
    serial_lora.py   LIVE: serial port reader, framing + decoder selection
    decoders.py      fc_uart_v1 (29-byte binary) and jsonl decoders -> FlightData
    xbee.py          XBee API-mode frame parsing + read-only RSSI query
    replay.py        plays back a recorded session CSV
  ascii_rocket.py    3D ASCII renderer of the .ork (shared logic with frontend/src/v3/asciiRender.ts)
  ascii_art.py       GENERATED by scripts/make_ascii_art.py; do not edit by hand

backend/tests/       pytest; one file per area
frontend/src/
  App.tsx            view switch (dashboard, telemetry, map, video, systems, mission, logs, settings)
  useTelemetry.ts    WebSocket client, rolling buffer, rAF-throttled re-render
  types.ts           mirrors backend schema.py; keep in sync
  prefs.ts           per-browser prefs in localStorage
  v3/shell.tsx       sidebar (VIEWS list), banner, collapse
  v3/panels.tsx      dashboard cards; v3/derive.ts derived values
  v3/*               Chart (uPlot), TrackMap, VideoView, LogoScene, SidebarRocket, icons
  styles.css         all styles; CSS variables for light/dark themes
```

## Data flow

```
source.events() -> TelemetryHub.handle_packet()
                     ├─ LinkStats.record()        (sequence gaps, RSSI, staleness)
                     ├─ history.append()          (in-memory, for late-joining clients)
                     ├─ recorder.write_frame()    (CSV, BEFORE broadcast)
                     ├─ broadcast {"type":"frame"} over /ws
                     └─ phase changed? -> FlightEvent -> recorder + broadcast {"type":"event"}
rejected bytes -> handle_rejected() -> rejected.csv + {"type":"rejected"}
```

WebSocket messages: `snapshot` on connect, then `frame`, `event`, `rejected`, `status`
(twice a second). A client too slow to keep up gets `resync` and reconnects for a fresh
snapshot, so ingestion never waits on a browser.
REST: `GET /api/status`, `GET /api/rocket`, `GET /api/mission` (team/vehicle/motor), `GET /api/sessions`, `POST /api/mode`
(switch source / start replay), `POST /api/sim` (simulator controls only).

Sessions are written to `data/sessions/<UTC>_<mode>/` as `telemetry.csv`, `events.csv`,
`rejected.csv`.

## Commands

```bash
# backend (from backend/)
python3 -m venv .venv && .venv/bin/pip install -e ".[dev]"
.venv/bin/python -m pytest -q             # all tests
.venv/bin/python -m ground_station        # http://127.0.0.1:8000, SIMULATION by default

# frontend (from frontend/)
npm install
npm run dev                               # http://localhost:5173, proxies to :8000
npm run build                             # type-check + build to frontend/dist (what CI runs)

# LIVE mode without hardware
.venv/bin/python -m ground_station.tools.fake_fc_uart          # prints a virtual port
.venv/bin/python -m ground_station --mode LIVE --serial-port /dev/ttysNNN
```

Before opening a PR: backend tests pass and `npm run build` succeeds. CI runs both
(Python 3.11 and 3.13; 3.13 is the Pi's version).

## How to add things

- **New packet format:** subclass `StreamDecoder` in `sources/decoders.py`. `feed(bytes)` buffers
  the stream and returns `SourcePacket`s, or `RejectedPacket`s for bytes that fail (raise and
  catch `PacketError` internally; never let a bad packet raise out). Register it in `DECODERS`
  (that name is the `serial.format` config value), add fixture bytes + a test, and document the
  byte layout in `docs/telemetry-schema.md`.
- **New receiver that isn't a line/stream serial port:** subclass `TelemetrySource`. Hub and UI
  don't change.
- **New telemetry field:** `schema.py` (FlightData + `CSV_COLUMNS`), `frontend/src/types.ts`,
  the decoder, `docs/telemetry-schema.md`, and a test. Old session CSVs must still replay.
- **New dashboard page:** add the id to `View` and `VIEWS` in `v3/shell.tsx`, a case in
  `App.tsx`, an icon in `v3/icons.tsx`, styles in `styles.css`.
- **New per-browser preference:** `prefs.ts`, key prefixed `gs.`, wrap localStorage in
  try/catch (it can throw).
- **Regenerate ASCII art:** `python3 scripts/make_ascii_art.py --temoc <image>`. Source images
  are not in the repo (UTD artwork; the club has permission to use the generated art).

## Conventions

- Python ≥ 3.11, type hints, pydantic models; tests with pytest.
- TypeScript strict; React function components and hooks; no UI framework; no new runtime
  dependency without a reason (the Pi serves everything offline).
- Units: SI internally (m, m/s, Pa, °C). The UI converts for display (`gs.units`).
- Comments explain *why*, in plain English.
- Git: branch per change (`feat/`, `fix/`, `docs/`, `ci/`, `chore/`), PR into `main`, merge
  when CI is green. `main` must stay launch-ready. See [docs/maintainers.md](docs/maintainers.md).
- macOS is case-insensitive: don't create two files whose names differ only by case.

## Gotchas

- Video capture (`getUserMedia`) only works in a secure context: open the dashboard at
  `http://localhost:8000` on the machine the capture device is plugged into.
- The Pi does not build the frontend at launch; `frontend/dist` must be built before going
  offline. `run-pi.sh` needs internet once to create the venv.
- `fc_uart_v1` has no CRC and no sequence counter (see open questions). Loss shows as "n/a".
- On the Pi, Chromium has had trouble loading `localhost`; `http://127.0.0.1:8000` is the
  reliable address.
